# Deployment Guide

This project is deployed from one GitHub monorepo as one Vercel project:

- Frontend: Vercel static Vite app built from the `frontend` directory.
- Backend: Vercel Express Function exposed under `/api` on the same domain.
- Database: TiDB Cloud MySQL-compatible database.

## 1. Vercel project

Use one Vercel project with the repository root as Root Directory.

Vercel project settings:

- Root directory: leave empty or set to repository root.
- Framework preset: Other.
- Install command: `npm --prefix backend ci && npm --prefix frontend ci`.
- Build command: `npm --prefix frontend run build`.
- Output directory: `frontend/dist`.

The root `vercel.json` contains these settings, so the project can also use the repository config directly.

## 2. Backend API

The backend is configured for Vercel with:

- `api/index.js` as the Vercel Express Function entry point.
- `/api/*` rewrites routed to that function.
- `backend/server/data/parking-cache/**` explicitly included in the function bundle.

Required backend environment variables in the same Vercel project:

```env
NODE_ENV=production
CLIENT_ORIGINS=https://your-app.vercel.app
FRONTEND_URL=https://your-app.vercel.app
JWT_SECRET=replace_with_at_least_32_random_characters
DB_HOST=gateway01.eu-central-1.prod.aws.tidbcloud.com
DB_PORT=4000
DB_USER=your_tidb_user
DB_PASSWORD=your_tidb_password
DB_NAME=ParkingApp
DB_SSL=true
DB_SSL_REJECT_UNAUTHORIZED=true
MAPBOX_ACCESS_TOKEN=your_mapbox_token
OPEN_CHARGE_MAP_API_KEY=your_open_charge_map_key
GOOGLE_CLIENT_ID=your_google_oauth_client_id
```

Optional email variables:

```env
SMTP_HOST=
SMTP_PORT=
SMTP_SECURE=false
SMTP_USER=
SMTP_PASS=
SMTP_FROM=
```

If SMTP variables are empty, the backend will not send real email. Password reset links are still generated by the backend logic, but production email delivery requires a configured SMTP provider.

## 3. Database

The production database is TiDB Cloud. The application should use `DB_NAME=ParkingApp`, not the default `sys` database from the TiDB connection string.

The schema has to contain:

- `users`
- `requests`

To initialize a new TiDB database:

```bash
mysql --ssl-mode=VERIFY_IDENTITY \
  --ssl-ca=/etc/ssl/cert.pem \
  -h gateway01.eu-central-1.prod.aws.tidbcloud.com \
  -P 4000 \
  -u your_tidb_user \
  -p < backend/server/config/schema.sql
```

Check the backend after deployment:

```bash
curl https://your-app.vercel.app/api/health
```

Expected response:

```json
{"status":"ok"}
```

## 4. Frontend

The frontend is a Vite app deployed by the same Vercel project. Vercel reads `VITE_` variables at build time, so every production change requires a redeploy.

Set these variables in the Vercel project:

```env
VITE_API_BASE_URL=/api
VITE_MAPBOX_ACCESS_TOKEN=your_mapbox_public_token
VITE_GOOGLE_CLIENT_ID=your_google_oauth_client_id
```

`VITE_API_BASE_URL` may also be omitted in production because the frontend defaults to `/api`.

## 5. Google OAuth

In Google Cloud Console, add the Vercel URL to Authorized JavaScript origins:

```text
https://your-app.vercel.app
```

Use the same OAuth Web Client ID in:

- Backend: `GOOGLE_CLIENT_ID`
- Frontend: `VITE_GOOGLE_CLIENT_ID`

## 6. Parking cache

The Baden-Baden parking cache is committed as a static GeoJSON file:

```text
backend/server/data/parking-cache/baden-baden.geojson
```

For deployment this is enough: the backend reads the file directly. If the cache needs to be regenerated:

```bash
npm run cache:parkings -- --bbox 8.15,48.70,8.35,48.85 --output backend/server/data/parking-cache/baden-baden.geojson
```

## 7. Deployment checklist

Before pushing:

```bash
npm run test
npm run build
```

After deployment:

```bash
curl https://your-app.vercel.app/api/health
```

- Open the Vercel URL.
- Register/login.
- Search for a place.
- Build a route.
- Check TOP-3 parking recommendations.
- Open parking details.
- Test Google login.
- Test password reset according to the configured email mode.
